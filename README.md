# Low-Latency Streaming TTS Pipeline, LiveKit Adapter & Voice Benchmark Suite

A real-time **LLM-to-Speech (TTS) streaming pipeline and automated evaluation suite** in Python (`asyncio`, `FastAPI`, `livekit-agents`, `piper-tts` ONNX, `Redis`, `Prometheus`, `faster-whisper`) built for low-latency phone and web AI voice agents in **English and German**.

---

## Description

In conversational phone AI, waiting for an LLM to finish generating an entire paragraph before calling Text-to-Speech (Batch TTS) creates a 1.5–2.5 second awkward silence before the caller hears a word.

This pipeline attempts to solve the four core engineering bottlenecks of real-time voice synthesis:
1. **Dynamic Clause Chunking & Backpressure (`asyncio.Queue`)**: Streams incoming LLM tokens and flushes speakable clauses on punctuation boundaries (`.`, `,`, `?`, `!`, `:`, `;`) while respecting abbreviations (`Dr.`, `Mr.`, `z.B.`) into a bounded `asyncio.Queue(maxsize=4)` to apply upstream backpressure.
2. **Multi-Tier Resilience & Filler Caching (`Redis` + `piper-tts`)**: Pre-warms common English & German conversational fillers (*"One moment please, let me check that for you."*, *"Einen Moment bitte, ich prüfe das sofort für Sie."*) in Redis/memory, uses CPU-native **Piper ONNX** neural voices (`en_US-lessac-medium`, `de_DE-thorsten-medium`), and wraps primary synthesis in `asyncio.wait_for()` with automatic failover to a deterministic fallback synthesizer.
3. **Sub-Millisecond Caller Barge-In (Turn-Taking)**: Listens for caller interruption events over WebSockets/LiveKit and immediately cancels active synthesis tasks and drains queued clauses in **`0.014 ms`**.
4. **Quantitative Before/After Evaluation & Observability**: Measures Time-to-First-Audio (TTFA), Real-Time Factor (RTF), Barge-In Cancellation Latency, and Round-Trip Intelligibility (TTS $\rightarrow$ Whisper STT Word Error Rate), exporting live histograms to **Prometheus** (`/metrics`).

## Measured Benchmark Results (Before vs. After)

Generated by running `python -m benchmarks.evaluate_tts` on CPU across English (`EN`) and German (`DE`) customer-support phone turns:

| Metric | Baseline (Batch TTS) | Optimized (Streaming Clause TTS) | Improvement |
| :--- | :--- | :--- | :--- |
| **Mean Time-to-First-Audio (TTFA)** | `1615.0 ms` | **`357.1 ms`** | **-77.9% Latency** |
| **TTFA (Un-cached Dynamic Clauses)** | `1615.0 ms` | **`550.6 ms`** | Concurrent LLM + TTS |
| **TTFA (With Filler Cache Hit)** | `1615.0 ms` | **`260.3 ms`** | Instant Filler Playback |
| **Mean Real-Time Factor (RTF on CPU)** | — | **`0.0816`** (`~12.3x` faster than real-time) | CPU ONNX (`piper-tts`) |
| **Round-Trip Intelligibility (Whisper WER)** | — | **`9.34%` WER** | Verified EN & DE Audio |
| **Barge-In Queue Drain & Cancel Latency** | — | **`0.014 ms`** | Sub-millisecond Interruption |


## Project Structure

```text
new_project/
├── app/
│   ├── main.py            # FastAPI server: /ws/tts WebSocket (with barge-in), /api/synthesize, /metrics
│   ├── pipeline.py        # AsyncClauseChunker, bounded asyncio.Queue backpressure, barge-in cancellation
│   ├── tts_engine.py      # ResilientTTSEngine: Redis/memory filler cache + Piper ONNX (EN/DE) + failover
│   ├── livekit_agent.py   # Custom LiveKit Agents AudioFrame TTS adapter & standalone demo
│   └── metrics.py         # Prometheus Histograms & Counters (TTFA, RTF, Barge-In, Cache Hits, Failovers)
├── benchmarks/
│   ├── evaluate_tts.py    # Automated Before/After TTFA, RTF & Faster-Whisper round-trip WER benchmark
│   ├── results.md         # Generated Markdown benchmark report
│   └── results.json       # Generated JSON telemetry report
├── static/
│   └── index.html         # Interactive Browser Voice & Barge-In Test Console
├── tests/
│   └── test_pipeline.py   # Pytest unit & asyncio concurrency tests
├── Dockerfile
├── docker-compose.yml     # Runs FastAPI TTS service, Redis 7, Prometheus, and LiveKit dev server
└── prometheus.yml
```

## Quick Start

#### 1. Local Python Setup
```powershell
python -m venv .venv
.\.venv\Scripts\pip install -r requirements.txt
```

#### 2. Run Unit & Concurrency Tests
```powershell
.\.venv\Scripts\pytest tests/ -v
```

#### 3. Run the Interactive Browser Console & FastAPI Server
```powershell
.\.venv\Scripts\uvicorn app.main:app --reload --port 8000
```
* Open **`http://localhost:8000`** to test English & German streaming synthesis, compare **Streaming vs. Batch** TTFA live, and click **Interrupt (Barge-In)** mid-sentence.
* Open **`http://localhost:8000/metrics`** to inspect the Prometheus histograms (`tts_ttfa_seconds`, `tts_rtf_ratio`, `tts_barge_in_latency_ms`).

#### 4. Run the LiveKit AudioFrame Adapter Demo
```powershell
.\.venv\Scripts\python -m app.livekit_agent --demo
```

#### 5. Run the Full Evaluation & Whisper WER Benchmark Suite
```powershell
.\.venv\Scripts\python -m benchmarks.evaluate_tts
```

#### 6. Run Full Stack with Docker Compose (FastAPI + Redis + Prometheus + LiveKit Server)
```powershell
docker compose up --build
```
